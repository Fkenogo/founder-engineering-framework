# FEF Programme Governance Pilot

**Pilot identifier:** FEF-PGP-001
**Establishing decision:** FAR-002-001
**Work package:** FEF-WPK-001B.6
**Status:** Operating Pilot — Phase 0
**Document type:** Informational pilot description
**Authority:** None beyond the cited programme records
**Standard status:** Not a governance standard

## 1. Purpose

The Programme Governance pilot organises and evaluates the programme-control practices used to execute development of FEF. It preserves the observed distinction between governing framework content and governing programme execution without prematurely creating permanent governance.

## 2. Scope

The pilot covers:

- programme status, sequence, and milestones;
- work-package administration;
- dashboards and programme health;
- dependencies and blockers;
- programme-level validation;
- programme change control;
- programme-management decision traceability.

## 3. Boundaries

Programme Governance concerns execution of the FEF development programme. Framework Governance concerns the framework itself, including its principles, constitution, authority, standards, and engineering methods.

The pilot:

- may record a dependency on a framework-governance decision;
- may not make that framework-governance decision;
- may report a standard’s status;
- may not approve, activate, adopt, or amend that standard;
- may control programme sequence within recorded Founder authority;
- may not create constitutional authority or another governance domain.

### 4.1 Preferred Review Mechanism

[FEF-WRP-001](FEF-WORK-PACKAGE-REVIEW-PACKAGE-PROTOCOL.md) and its [Review Package template](../templates/FEF-WORK-PACKAGE-REVIEW-PACKAGE-TEMPLATE.md) are Founder-approved for pilot use as the preferred review-handover mechanism for prospective work packages.

This recognition is:

- a preferred operating practice;
- prospective;
- non-mandatory;
- not a governance standard;
- not authority for a coding agent to complete Founder disposition;
- not a requirement to rewrite historical work packages.

Pilot use should be observed for review speed, clarity, traceability, proportionality, and preservation of the Founder-only checkpoint.

## 5. Pilot Lifecycle

| Stage | Purpose | Exit Evidence |
|---|---|---|
| Established | Record architecture, boundaries, artefacts, and validation criteria | FAR-002 and FEF-WPK-001B.6 validation |
| Operating | Use the artefacts throughout remaining Phase 0 work | Updated records and work-package evidence |
| Observed | Record usability, conflicts, overhead, omissions, and boundary issues | Programme health and validation evidence |
| Evaluated | Compare evidence with FAR-002 criteria | Evaluation report or Founder review record |
| Founder Disposition | Continue, revise, end, defer, or separately authorise standardisation work | Express Founder decision |

No stage automatically creates permanent status.

## 6. Success Criteria

The pilot succeeds if it demonstrates that:

1. the Founder can determine current programme position rapidly;
2. every work package has one clear status;
3. one immediate next work package is identifiable;
4. sequence, milestones, blockers, and dependencies remain consistent;
5. programme decisions are traceable to authority;
6. Programme Governance remains separate from Framework Governance;
7. programme controls remain proportionate;
8. no pilot artefact is mistaken for a governance standard.

## 7. Failure or Review Indicators

Review should be triggered if:

- multiple records claim conflicting programme status;
- the pilot changes framework governance or standard content;
- the critical path changes without express authority;
- programme controls impose disproportionate overhead;
- a pilot artefact is treated as constitutional or standards authority;
- Phase 0 ends;
- permanent status or a standard is proposed.

## 8. Current Operating Position

Pilot establishment does not change programme execution:

- the Master Programme remains controlling;
- FEF-WPK-001B.6 is completed after validation;
- FEF-WPK-001B.5 remains blocked by missing Founder-approved review evidence;
- FEF-WPK-001B.5 remains the immediate next work package;
- no downstream work is authorised by this pilot.

## 9. Evaluation Recommendation

The proposal that every new governance domain should first operate successfully as a pilot is retained as a recommendation for evaluation. It is not an adopted rule and must not be applied outside this pilot without later Founder authority.
