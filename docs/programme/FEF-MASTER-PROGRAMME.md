## 1. Purpose and Precedence

This document is the single authoritative programme management record for the Founder Engineering Framework. It reconciles the repository state, programme sequence, work-package status, dependencies, and immediate next activity.

For programme status and sequencing, this document takes precedence over the initial roadmap, programme initiation record, work-package register, and dashboard where those records differ. Those records retain their historical, administrative, or navigation purposes.

This precedence does not make the Master Programme a governance standard and does not alter the authority or approval status of any FEF standard, decision, review, or constitutional proposal.

### 1.1 Programme Authority Model — Single Source of Truth

Adopted 2026-08-04, on Founder recommendation, as a permanent programme-governance
architecture principle:

> **The Master Programme (FEF-MP-001) is the single authoritative source of
> programme state. All other programme documents are consumers of that
> state, not independent controllers of it.**

This document — and only this document — is authoritative for:

- current programme position and lifecycle state;
- current and active work package;
- current review domain and domain lifecycle state (Mobilised, Active,
  Closed, Uncommenced, etc.);
- immediate next governed activity;
- completion status of controlled work packages and deliverables;
- authorised execution sequence; and
- dependencies and programme readiness.

Other programme documents shall not independently determine, assert, or
duplicate "where the programme is." Specifically:

| Document | Role Under This Model |
|---|---|
| [FEF-FOUNDER-DASHBOARD.md](FEF-FOUNDER-DASHBOARD.md) | Navigation and executive-view document. Summarises and links to this Master Programme; does not independently maintain programme state. |
| [FEF-FGR-002-REVIEW-IDENTITY.md](../governance/reviews/FEF-FGR-002/FEF-FGR-002-REVIEW-IDENTITY.md) | Holds review identity, review metadata, and controlled-register identifiers for FEF-FGR-002 only. Does not independently restate current programme-level position beyond what is intrinsic to identifying the review and its own controlled registers. |
| [FEF-DOCUMENT-MANIFEST.md](FEF-DOCUMENT-MANIFEST.md) | Registers the existence, location, and category of controlled artefacts. Does not independently assert programme status; status columns reference this Master Programme rather than restate it. |
| All other programme records | Retain their historical, administrative, or navigation purposes (§1) and must not be read as competing sources of current programme state. |

**Update rule going forward:** whenever programme state changes, update only
the Master Programme, unless another document's own constitutional purpose
(review identity, document registration, or a distinct governance authority)
independently requires a change. Documents that merely repeat programme
status must reference this Master Programme instead of duplicating it.

This model does not alter constitutional documents, Founder wording,
mobilisation authority, review authority, Framework Evolution boundaries, or
any protected historical record. It is a forward-looking programme-control
architecture; it does not retroactively rewrite historical narrative, change
history, or append-only version entries in any document, including this one.

## 3. Status Definitions

| Status     | Programme Meaning                                                                                                                         |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Completed  | Required deliverables and validation for the work package are recorded as complete.                                                       |
| Active     | The Founder has authorised the work package and it is the current execution focus.                                                        |
| Pending    | Planned or anticipated work that is not currently authorised for execution or cannot yet start because its sequence has not been reached. |
| Blocked    | Authorised or planned work cannot proceed because a named prerequisite or decision is absent.                                             |
| Cancelled  | Work has been expressly cancelled.                                                                                                        |
| Superseded | Work has been expressly replaced by another controlled item.                                                                              |

“Completed” describes work-package delivery only. It does not imply that an associated standard is approved, active, adopted, effective, or authoritative.

## 11. Change Control

The Master Programme must be updated:

- when a work package is completed, blocked, cancelled, superseded, or authorised;
- before a new work package is authorised;
- when a controlling dependency or programme sequence changes;
- when a programme-level Founder decision changes status or sequencing.

Updates must preserve historical traceability and must not be used to infer governance approval.
