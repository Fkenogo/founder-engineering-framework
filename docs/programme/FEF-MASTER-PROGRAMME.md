## 1. Purpose and Precedence

This document is the single authoritative programme management record for the Founder Engineering Framework. It reconciles the repository state, programme sequence, work-package status, dependencies, and immediate next activity.

For programme status and sequencing, this document takes precedence over the initial roadmap, programme initiation record, work-package register, and dashboard where those records differ. Those records retain their historical, administrative, or navigation purposes.

This precedence does not make the Master Programme a governance standard and does not alter the authority or approval status of any FEF standard, decision, review, or constitutional proposal.

## 3. Status Definitions

| Status     | Programme Meaning                                                                                                                         |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Completed  | Required deliverables and validation for the work package are recorded as complete.                                                       |
| Active     | The Founder has authorised the work package and it is the current execution focus.                                                        |
| Pending    | Planned or anticipated work that is not currently authorised for execution or cannot yet start because its sequence has not been reached. |
| Blocked    | Authorised or planned work cannot proceed because a named prerequisite or decision is absent.                                             |
| Cancelled  | Work has been expressly cancelled.                                                                                                        |
| Superseded | Work has been expressly replaced by another controlled item.                                                                              |

“Completed” describes work-package delivery only. It does not imply that an associated standard is approved, active, adopted, effective, or authoritative.

## 11. Change Control

The Master Programme must be updated:

- when a work package is completed, blocked, cancelled, superseded, or authorised;
- before a new work package is authorised;
- when a controlling dependency or programme sequence changes;
- when a programme-level Founder decision changes status or sequencing.

Updates must preserve historical traceability and must not be used to infer governance approval.
