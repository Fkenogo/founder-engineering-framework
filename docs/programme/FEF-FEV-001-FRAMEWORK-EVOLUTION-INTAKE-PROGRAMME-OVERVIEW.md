## 1. Purpose

The Framework Evolution Intake Programme establishes the controlled governance mechanism through which engineering lessons from Founder projects are submitted, evaluated, prioritised and, where appropriate, recommended for future Framework Evolution.

This programme does **not** amend the Founder Engineering Framework. It establishes how future framework improvements will be considered.

## 2. Scope

### 2.1 In Scope

- Receiving cross-project engineering observations;
- Distinguishing project-specific lessons from framework-wide lessons;
- Preserving engineering evidence;
- Enabling Founder review and prioritisation;
- Avoiding unnecessary governance overhead.

### 2.2 Out of Scope

- Amending approved FEF governance instruments;
- Creating new governance domains;
- Adding lifecycle stages to D1–D4 or DG-1–DG-6;
- Approving or rejecting submitted candidates;
- Performing Framework Evolution.

## 3. Principles

The intake programme is guided by the following principles:

1. **Evidence before opinion** — submissions must be grounded in observable engineering practice;
2. **Commonality before adoption** — framework changes require evidence of cross-project applicability;
3. **Stability before change** — the framework shall not change until stability is demonstrated;
4. **Proportionate governance** — intake overhead shall not exceed the value of the lesson;
5. **Project autonomy** — individual projects retain ownership of product-specific architecture, repositories, engineering programmes, and delivery governance.

## 4. Relationship to the Master Programme

The Framework Evolution Intake Programme operates as a **supporting programme** to the Master Programme (FEF-MP-001).

| Relationship      | Description                                                   |
| ----------------- | ------------------------------------------------------------- |
| Submission source | Engineering lessons from Founder projects                     |
| Registration      | Framework Evolution Candidate Register (FEF-FEV-001-FECR-001) |
| Evaluation        | Framework Evolution Review Guide (FEF-FEV-001-FERG-001)       |
| Recommendation    | Founder review and prioritisation                             |
| Implementation    | Separate authorised Framework Evolution work package          |

The intake programme does not alter the authorised programme sequence in the Master Programme. D5 is Closed; D6 remains Uncommenced and requires its own separately governed mobilisation and entry sequence. No Framework Evolution activity has commenced.

## 6. Non-Effects

This programme overview:

- does not amend constitutional documents;
- does not modify D1–D4 outputs;
- does not commence D5 or D6;
- does not perform Framework Evolution;
- does not approve or reject submitted candidates;
- does not create additional governance domains;
- does not introduce unnecessary lifecycle stages.
